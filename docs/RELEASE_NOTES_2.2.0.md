# SAT2 Relay 2.2.0 Local Closed Loop

This release keeps the 2.x local, single-user design and adds guided multi-session automatic progression.

## Added

- Guidance Capsule 2.2 with delivery-scoped `delivery_token`.
- Minimal Session Decision JSON marker: `SAT2_RELAY_DECISION`.
- Browser extension detection and manual fallback button for the current Decision.
- Daemon Decision API that composes all Relay control fields deterministically.
- Local publish gate for state, role, parent event, PR head, path scope, and delivery-token validation.
- Bidirectional routing for Worker-to-Mentor and Mentor-to-Worker events.
- Decision outbox with idempotency and publish-uncertain recovery by event marker search.
- Dashboard outbox view and human-confirmation gate for `MENTOR_ACCEPTED`.
- Dashboard task authorization entry point so first authorization can be generated by Relay rather than hand-written YAML.

## Preserved boundaries

- No automatic merge.
- No automatic qualification.
- No formal experiment dispatch.
- No registry, seed, output, evidence, or paper update.
- No large multi-machine control plane, key rotation, or distributed publisher model.

## Minimal expected loop

```text
Task authorized from Dashboard
→ Worker receives Capsule
→ Worker emits Decision JSON
→ Relay publishes Worker checkpoint
→ Mentor receives review Capsule
→ Mentor emits changes-required or accepted Decision JSON
→ Relay routes the next Capsule
```
